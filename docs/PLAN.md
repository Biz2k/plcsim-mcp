# План работ

Состояние на 08.10.2026: Проект `plcsim-mcp` выделен из основного `tiaportal-mcp`. Базовые заглушки созданы (31 инструмент).

В будущем проект планируется объединить обратно в «TIA Portal AI Engineering Toolkit», так что стиль и структура должны совпадать с `tiaportal-mcp`.

## Основные направления разработки (TODO)

1. **Жизненный цикл инстансов (Instances)**
   - Реализовать список, создание (с проверкой типа), удаление инстансов.
2. **Управление состоянием (Power / Operating State)**
   - Power On/Off, Run/Stop, MRES.
3. **Настройка сети (Networking)**
   - Конфигурация интерфейсов, IP Маппинг. (Это самая сложная часть, опираемся на опыт `PLCsim-Advanced-Manager`).
4. **Работа с тегами (Tag Access)**
   - Одиночное и Пакетное (batch) чтение и запись значений тегов по именам.
5. **Снимки памяти (Snapshots)**
   - Сохранение/восстановление состояния (профили).
6. **Виртуальная память (SD Card)**
   - Управление виртуальной картой памяти (монтирование/очистка).

## Текущие задачи (Пошаговый план разработки)

**Шаг 1: Доработка базового жизненного цикла и состояний [ВЫПОЛНЕНО]**
- Улучшены текущие заглушки создания (`plcsim_create_instance`) и удаления инстансов: добавлена проверка на существование имени, корректная обработка исключений.
- Доработаны команды `plcsim_power_on`, `plcsim_power_off`, `plcsim_run`, `plcsim_stop` и `plcsim_memory_reset`, теперь они проверяют текущий статус (Operating State) перед выполнением действия.
- **[НОВОЕ]** Запуск и остановка самого процесса/сервиса PLCSIM Advanced на хост-машине (Start/Stop PLCSIM Host Process).

**Шаг 2: Реализация сетевого маппинга [ВЫПОЛНЕНО]**
- Разделены инструменты глобальной сети (NetworkMode) и маппинга инстанса (InterfaceMapping, IPSuite).
- Опирались на код-референс `PLCsim-Advanced-Manager` для правильной привязки виртуальных интерфейсов ПЛК к реальным адаптерам Windows (NetworkMode, InterfaceBinding).

**Шаг 3: Пакетная работа с тегами и улучшение типов**
- Реализовать инструменты `plcsim_batch_read` и `plcsim_batch_write` для обмена массивами тегов за один вызов (для производительности).
- Расширить преобразование типов (SDataValue) при записи, чтобы поддерживались все базовые типы Siemens.

**Шаг 4: Структурирование по стандартам TIA MCP (Подготовка к слиянию) [ВЫПОЛНЕНО]**
- Вынесены инструменты из файла `PlcSimServer.Tools.cs` в логические блоки: `PlcSim.Instances.cs`, `PlcSim.States.cs`, `PlcSim.Tags.cs`, `PlcSim.Network.cs`, `PlcSim.Profiles.cs`, `PlcSim.Global.cs`.
- Код готов к внедрению распределения инструментов по группам (`ToolGroups.cs` и `ToolSets.cs`), как это сделано в основном TIA Portal сервере.

**Шаг 5: Скрипты тестирования (Quality Assurance)**
- Создать скрипт `tools/smoke.ps1`, который автоматически создаст виртуальный ПЛК, включит его, настроит сеть, запишет/прочитает тег и удалит инстанс.

## Идеи на будущее (Отложенные концепции)

- **Поддержка обычного S7-PLCSIM (Basic)**: Добавить в сервер библиотеку S7.Net (или Sharp7) для прямой TCP-коммуникации по порту 102. Это позволит читать/писать теги в базовой версии PLCSIM, если пользователь запустит фоновую утилиту `NetToPLCsim` для проброса трафика. Это сделает сервер универсальным для чтения/записи логики без лицензии Advanced.
